# Движок и CLI: этап 1

## Реализация

`eagle-engine` принимает `Source`: фабрику `Read + Seek + MediaSource` и сигнал
отмены. Он не знает о провайдерах, HTTP, токенах или структуре кэша.
`eagle-app` выбирает закреплённую копию любого качества, полный кэш выбранного
качества, затем сеть. Выбор повторяется при каждом открытии, включая будущий
трек очереди. `CacheLease` защищает активный файл от LRU до закрытия reader;
аренда не меняет постоянное закрепление. Последний сетевой reader останавливает
свой downloader перед освобождением аренды. Одновременные процессы с одним
каталогом данных не поддерживаются.

`eagle-net::growing::Location` содержит `SignedUrl` и необязательный срок действия.
Ссылка обновляется перед следующим диапазоном после истечения и после 401/403/410.
Диапазоны по 2 МиБ записываются на диск; reader ждёт отсутствующие данные,
не выдавая дыру как EOF. Приоритет принадлежит reader и применяется при запросе
данных. Проверяются Content-Range, размер ответа и ETag. Обрыв ответа — ошибка;
смена ETag инвалидирует карту. Без Range поддерживается последовательное чтение,
а пользовательская перемотка за загруженную часть отклоняется.

Декодирование, ресемплинг и открытие источников выполняются в рабочем потоке.
CPAL callback читает ограниченное кольцо PCM, применяет громкость и ramp,
обновляет атомарные счётчики; не читает сеть или диск. Debug-тест проверяет
отсутствие аллокаций callback. При пустом буфере выводится тишина и фиксируется
underrun. PCM-буфер настраивается от 2 до 20 секунд; значение по умолчанию — 2.

Движок публикует состояния, смену трека, ошибки, статистику и позиционные якоря
с прогнозируемым временем слышимости. Команды отменяют заблокированный reader.
Перемотка использует точную позицию декодера либо повторное чтение от начала.
Предзагрузка подготавливает следующий трек; одинаковые входные частоты сохраняют
историю ресемплера через границу. При смене частоты остаток фильтра выгружается.
Восстановление опирается на слышимый трек, даже если в кольцо уже записан следующий.

## Поддержка форматов

Автоматические тесты проверяют mono/stereo и 44,1/48 кГц локально, по HTTP с Range
и без Range. Opus декодируется в 48 кГц независимо от частоты исходного PCM.

| Формат | Ограничение длины / gapless | Результат автоматической проверки |
| --- | --- | --- |
| MP3 | LAME/Xing trim; оценочное число кадров без индекса не обрезает звук | Матрица, VBR с индексом/без, seek и split-контроль |
| ADTS AAC-LC | Оценочная длительность не задаёт конец; delay не угадывается | Матрица и длинный VBR, допускается encoder delay/padding |
| M4A AAC-LC | iTunSMPB или простой edit list с rate 1; moov ≤4 МиБ | Матрица, seek и тесты разбора trim |
| FLAC | Точное исходное число кадров | Матрица и границы очереди |
| Ogg Vorbis | Packet trim и конечное число кадров | Матрица, включая последний granule |
| Ogg Opus | pre-skip и конечный granule | Матрица; mapping family 0, без chained streams |
| WAV PCM | Точное число кадров | Локальный контроль seek, split и ресемплера |

HLS, шифрованные потоки, многоканальный звук и chained Opus отклоняются.
Синтетические фикстуры и воспроизводимый генератор: `bench/generate_audio.py`.
Звук провайдеров и подписанные ссылки не входят в Git.

## Проверки

Локально на macOS выполнены:

- `cargo fmt --all --check`, clippy всех targets с `-D warnings`;
- `cargo test --workspace --locked`: 52 теста, включая HTTP-матрицу;
- `python3 -m unittest discover -s bench`: 7 тестов;
- `cargo check --workspace --all-targets --locked` с Rust 1.89.0;
- cargo deny, cargo audit и отдельная лицензирующая конфигурация iOS;
- gitleaks исходников и истории без находок;
- PTY-сценарии паузы, перемотки, продолжения, next, `q` и ошибки:
  режим терминала восстановлен, в успешных сценариях underruns не наблюдались.

HTTP-тесты отдельно проверяют отмену заблокированного чтения, смену ETag,
401/403/410, срок действия ссылки и обрыв ответа. Тесты хранилища подтверждают
LRU и освобождение последней аренды; тест приложения повторно открывает источник
после удаления кэша и читает полный кэш без HTTP. Смешанная очередь проверяет
границы и позиции каждого трека. Split/continuous сравнение проверяет сохранение
истории ресемплера; lossy-контроль использует явный допуск RMS.

CI сохраняет desktop Linux/macOS/Windows, MSRV, dependencies, Android и iOS.
CI Linux/macOS/Windows, Android, iOS, MSRV и dependencies прошёл: [запуск](https://github.com/9LEsko9/eagle/actions/runs/43180968053).

## Методика замеров

Release после стабилизации скопирован в исключённый из Git каталог
`bench/results/stage-one-binary`, доступ только для чтения. SHA-256:
`9810216719b5c90794d14c7e32bd51a376bd4f7bd95a971a3a4f5a24d30e7a62`.
Во время матрицы локальные сборки не запускаются.

Матрица: буфер 2/5/10/20 секунд × файл/локальный HTTP × вход 44,1/48 кГц,
выход 44,1 кГц. По три окна 60 секунд после 3 секунд прогрева; каждый процесс
получает отдельный пустой кэш. Входы — четырёхминутные синтетические MP3.
Частота выхода проверяется замерщиком: неподходящее устройство завершает замер
ошибкой, а не создаёт ложную строку «ресемплинг».

```sh
python3 bench/audio_matrix.py \
  --binary bench/results/stage-one-binary/eagle-cli \
  --audio /path/to/44100.mp3 --audio-resampled /path/to/48000.mp3 \
  --prelude crates/engine/tests/fixtures/tone-44100-2.flac \
  --output docs/measurements/engine-matrix.csv
```

CPU — процент одного ядра; память — macOS phys_footprint, снимки раз в секунду.
Пик в CSV — наблюдавшийся, не точный пик ОС. Счётчики движка поступают раз в секунду
и могут отставать от снимков ОС. HTTP/байты — тела ответов, без TLS/TCP/заголовков.
Счётчики process package-idle/interrupt wakeups не измеряют радиомодуль.
Обычная рабочая машина с другими приложениями; их нагрузка не контролируется.

Исходные данные: [CSV](measurements/engine-matrix.csv), [условия и хэши](measurements/engine-matrix.json).
Сохранено 31 из 48 запланированных окон; длительная матрица остановлена при завершении текущей сдачи. Во всех завершённых окнах underruns: 0. Полная приёмка матрицы и предела 30 МиБ остаётся открытой.

Буфер 2 секунды прошёл все 12 окон без underruns; это минимальный проверенный буфер.
CPU в этих окнах: 0.48–0.65% одного ядра.


Baseline rodio: [спайк и ограничения](engine-format-spike.md),

## Повтор и смена порядка во время воспроизведения

`Engine::configure_playback` задаёт порядок постоянных индексов источников и
режим `Repeat::{Off, All, One}`. Desktop меняет эти параметры без пересоздания
движка, открытия аудиоустройства и перемотки текущего трека. Повтор подготавливает
следующий проход внутри движка, сохраняя выходной поток. Ручной Next выбирает
следующий элемент порядка даже при Repeat One.

Смена политики подтверждается аудиопотоком на границе callback. Уже переданные
устройству кадры сохраняются; устаревшие будущие кадры исключаются. Индексы
источников сохраняются при перемешивании и повторе, включая разные вхождения
одного TrackId. Состояние паузы и позиция текущего трека не сбрасываются.

Кадровые тесты проверяют повтор, порядок и смену будущих треков с ресемплингом.
Они не заменяют прослушивание на устройстве: при переключении в последний момент
новому источнику может понадобиться время на загрузку. При отсутствии его PCM
допустима буферизация, но кадры из отменённого порядка воспроизводиться не должны.

## Отложенная приёмка

VK, Bluetooth, смена аудиоустройства и сон отложены пользователем: сейчас не
проверялись и не считаются пройденными. Обработчики восстановления и тесты
состояния не заменяют аппаратную приёмку. Native уведомления пробуждения
реализованы для macOS; остальные платформы используют общую обработку ошибок
аудиоустройства, без отдельного native power hook.

Предел 30 МиБ оценивается по фактическим замерам: превышение нельзя закрывать
изменением методики или исключением неудобных строк. Прямые радиопробуждения,
живое принудительное истечение подписанной ссылки и все варианты потоков
провайдеров этой матрицей не подтверждены.

Известное ограничение: отмена будит заблокированный reader, но Drop downloader
ожидает HTTP-worker; при зависшем ответе выход/next может задержаться до сетевого
таймаута. Исправление жизненного цикла worker остаётся открытым.
