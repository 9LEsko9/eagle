# Спайк транспорта и baseline до замены rodio

Состояние на 2026-11-12. Это наблюдения выбранных потоков и явные ограничения
проверки. Они не описывают все варианты, доступные провайдерам.

## Наблюдения Яндекса

В существующей учётной записи проверены три разных трека, каждый в high и
standard. Инструмент: `cargo run -p eagle-app --example stream_spike --
yandex:128582477 yandex:130011719 yandex:130176261`. Токен читается из keyring;
токен и подписанный URL не выводятся. Каждый запрос читает первые 65 536 байт.

| ID | Качество | Размер файла по Content-Range | HTTP | ETag | Заявленный кодек / сигнатура |
| --- | --- | ---: | ---: | --- | --- |
| 128582477 | high | 3 707 298 | 206 | есть | MP3 / MPEG audio |
| 128582477 | standard | 2 224 378 | 206 | есть | MP3 / MPEG audio |
| 130011719 | high | 3 651 918 | 206 | есть | MP3 / MPEG audio |
| 130011719 | standard | 2 191 151 | 206 | есть | MP3 / MPEG audio |
| 130176261 | high | 4 162 873 | 206 | есть | MP3 / MPEG audio |
| 130176261 | standard | 2 497 724 | 206 | есть | MP3 / MPEG audio |

Все шесть ответов содержали `Content-Range: bytes 0-65535/<размер>`.
Выбранный адаптер возвращает прямой HTTP-файл и `Encryption::None`.
Манифест сегментов на этом пути не использовался. Это не доказывает отсутствие
HLS, lossless или шифрованной доставки в других API Яндекса. Битрейт — политика
выбора адаптера (до 320/192 кбит/с), а не отдельный инструментальный замер этих
шести файлов. Delay/padding этих живых вариантов отдельно не извлекались.
Они остаются непроверенной частью спайка, даже если локальный декодер умеет
читать LAME/Xing из подходящего файла.

## VK и отложенные транспорты

VK не проверен. Владелец разрешил учётную запись, но доступ к браузеру оказался
недоступен двумя инструментами; затем владелец попросил отложить эту часть.
Ни качество, ни кодек, ни шифрование VK здесь не предполагаются. Спайк обоих
провайдеров остаётся открытым критерием приёмки.

Будущие HLS/шифрованные транспорты требуют отдельных подготовленных источников:
разбор master/media playlist, выбор варианта, временную шкалу сегментов,
инициализационные сегменты, discontinuity и обновление плейлиста;
авторизацию и обновление ключей по подтверждённому контракту провайдера;
сборку seek-карты и проверяемый кэш сегментов. Нельзя подставлять HLS-URL
в обычный `Read + Seek` и считать поддержку реализованной.

## Матрица v1

| Контейнер / кодек | Декодер | Источник обрезки | Ограничения |
| --- | --- | --- | --- |
| MP3 | Symphonia 0.5.5 | packet trim / LAME/Xing, объявленная длина | Нет угадывания delay без метаданных |
| ADTS / AAC-LC | Symphonia 0.5.5 | достоверная обрезка обычно отсутствует | Encoder delay не вычитается наугад |
| M4A / AAC-LC | Symphonia 0.5.5 | iTunSMPB либо простой MP4 edit list | Только один непрерывный edit с rate 1; moov до 4 МиБ |
| FLAC | Symphonia 0.5.5 | исходное число кадров | Mono/stereo |
| Ogg / Vorbis | Symphonia 0.5.5 | packet trim и объявленное число кадров | Проверены короткие файлы с последней granule position |
| Ogg / Opus | ogg 0.9.2 + opus 0.4.0 / libopus | pre-skip и конечная granule position | Mapping family 0, mono/stereo; chained Opus отклоняется |

Это целевая матрица реализации. Фактические результаты тестов и аппаратной
приёмки фиксируются в [engine.md](engine.md). Официальная
[матрица Symphonia](https://docs.rs/symphonia/0.5.5/symphonia/) не содержит Opus
и не заявляет gapless AAC/MP4. Поэтому Opus использует отдельный адаптер, а
обрезка M4A читается дополнительно. [opus](https://docs.rs/opus/0.4.0/opus/)
предоставляет привязки к libopus; актуальный `opusic-sys` собирает включённые исходники libopus.

## Baseline rodio

Исходный код — `922e55b`, release, Mac14,15, Apple M2, 8 ГиБ, Darwin 27.2.0.
Три последовательных окна 60 секунд после двух секунд прогрева, один MP3 из
полного кэша. CPU измеряется в процентах одного ядра с правильным переводом
Mach ticks; Python ABI-тест проверен через независимый `time.process_time()`.

| Окно | CPU одного ядра, % | phys_footprint, байт | HTTP / байты |
| --- | ---: | ---: | --- |
| 1 | 1.2066 | 5 554 848 | 0 / 0 |
| 2 | 1.1830 | 5 554 848 | 0 / 0 |
| 3 | 1.1947 | 5 620 384 | 0 / 0 |

В каждом окне: 0 package-idle wakeups и 2 interrupt wakeups процесса.
Исходные значения опубликованы в [CSV](measurements/rodio-baseline.csv),
параметры, SHA-256 бинарника и входа — в [JSON](measurements/rodio-baseline.json).
Это обычная рабочая macOS с другими приложениями, а не изолированная машина.
Аудио и бинарник остаются вне Git. CPU-пробуждения процесса не измеряют радио.
