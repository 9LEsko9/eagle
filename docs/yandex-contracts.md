# Yandex Music: контракты desktop beta

Проверено 2026-11-13. Это исследование, а не утверждение о стабильном публичном API Яндекса. Официальной спецификации этих операций не найдено. Ниже ссылки на исходный код независимого неофициального клиента; его запросы являются свидетельством реализации клиента, но не подтверждают текущее поведение сервера или права аккаунта.

## Подтверждено в Eagle

Тесты с локальным HTTP-сервером проверяют формирование запросов и разбор фиктивных ответов, в том числе создание и удаление плейлиста, полные snapshot и радио. Сами fixtures не подтверждают API на реальном аккаунте; live-наблюдения перечислены ниже. `Provider` содержит snapshot, позиционное редактирование плейлиста и получение радиосессии/партий, но не отправку истории или feedback.

Тест восстановления 100 загрузок заранее создаёт локальные PNG обложек и цвета, затем проверяет сохранённые URI и декодирование обоих размеров после аварийного завершения и офлайн-перезапуска. Загрузку обложек по сети этот тест не проверяет.

## Проверка аккаунта и оставшиеся ручные проверки

Read-only проверка аккаунта: `GET /rotor/stations/dashboard` вернул объект со `stations`, `GET /rotor/stations/list?language=ru` — список из 699 элементов, `GET /rotor/account/status` — объект, `GET /music-history?fullModelsCount=0` — объект с `historyTabs`. Содержимое и идентификаторы не сохранялись. Это подтверждает доступность ответов для одного аккаунта, но не контракт записи истории.

[Неофициальный клиент](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/radio.py) описывает `GET /rotor/station/{station}/tracks?settings2=True` как получение цепочки и запуск потока. Поскольку отсутствие создания сессии не доказано, запрос в этой проверке не выполнялся. Для актуальной сессии [источник клиента](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/rotor_sessions.py) описывает `POST /rotor/session/new` с JSON `{"seeds":["user:onyourwave"]}` как создание сессии, а `POST /rotor/session/{session_id}/tracks` — как получение очередной партии с необязательным feedback. С отдельного разрешения создана одна тестовая сессия с `incognito: true` и запрошена следующая партия с пустой очередью без feedback: оба ответа содержали по пять треков, `radioSessionId` и `batchId` были строками, `unknownSession` во второй партии был `false`. Между партиями были повторяющиеся треки. Воспроизведение и feedback не выполнялись; влияние создания сессии на историю не установлено, а `incognito` само по себе его не доказывает.

- Плейлисты: [исходник клиента](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/playlists.py) отправляет `POST /users/{uid}/playlists/{kind}/change` с `kind`, `revision`, `diff`; вставка использует track и album ID, удаление — диапазон позиций. Happy path проверен на отдельном плейлисте. Формат ошибок при конфликте и атомарность при сбое не установлены. Дубли требуют позиции и ревизии; album ID берётся из записи плейлиста, а не из первого альбома вложенного трека. При отсутствии этого поля перемещение запрещено.
- Радио: [исходник клиента](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/rotor_sessions.py) описывает создание сессии, получение следующей партии и события начала радио, начала, окончания и пропуска трека. Начальная и следующая партии без feedback проверены. `session_id` и `batch_id` нельзя смешивать между сессиями. Контракт feedback и гарантия неповторяемости партий не подтверждены. Автоматическая отправка feedback в рамках исследования не разрешена.
- История: [клиент](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/music_history.py) содержит чтение истории; это не доказательство контракта записи прослушивания. Нужны отдельные данные о записи и дедупликации. Не отправлять реальные события при исследовании.
- Доступ: `available=false`, отсутствие подписки, ошибки сети и отдельный 403 сами по себе не доказывают окончательную потерю доступа к сохранённому треку. Успешный `resolve_stream` и сведения о текущей подписке тоже не определяют окончательный отзыв. Нужен определённый провайдером и проверенный авторитетный сигнал; до этого результат `Unknown`.

После подтверждённого входа на отдельном тестовом плейлисте проверены создание, чтение revision, вставка двух треков с повтором первого и порядок после чтения, отклонение устаревшей revision без изменения состояния, переименование, перестановка через один diff из удаления и вставки, удаление трека и самого плейлиста. После каждой операции выполнено независимое чтение; удалённый плейлист отсутствует в списке. Точный статус и тело ошибки устаревшей revision и изменение revision при переименовании не зафиксированы. Атомарность при сбое не проверена. Другие плейлисты, лайки и события не изменялись. Приватный журнал сохранён локально для контроля очистки.

## Не реализовано / неопределённость повтора

Контракты snapshot и позиционного редактирования подключены к `Provider`, Session и интерфейсу. Добавление текущего трека передаёт точные track/album ID; меню строки передаёт ID плейлиста, ревизию и позицию. На аккаунте проверено перемещение только в одном направлении. Тип и содержимое серверной ошибки конфликта не установлены; после неопределённого POST приложение перечитывает состояние, но не повторяет изменение. Переименование остаётся неподключённым до проверки его ревизий.

Настройка волны («Моя волна»: настроение, знакомое/новое, «Ещё такого») передаётся в `seeds` запроса `POST /rotor/session/new`: `user:onyourwave` (или `track:<id>` для «Ещё такого»), затем `settingMoodEnergy:{fun|active|sad|calm}` и `settingDiversity:{favorite|discover}`. Направления настроения сводятся так: светлое и весёлое — `fun`; энергичное и дерзкое — `active`; мрачное и грустное — `sad`; тихое и спокойное — `calm`; близко к центру настройка не отправляется. Новизна меньше 0,36 — `favorite`, больше 0,64 — `discover`, между ними настройка не отправляется. Эти имена основаны на описании полей неофициального клиента и поведении веб-клиента, но в этой проверке живыми запросами не подтверждены: сервер может игнорировать или отклонять неизвестные значения. Тесты проверяют только формирование тела запроса.

Создание радиосессии и получение следующей партии подключены к провайдеру и экрану «Моя волна»; сетевой запрос выполняется по действию пользователя. Порядок и повторы сохраняются. Очередь хранит контекст каждого вхождения, а история, outbox и локальный radio intent записываются транзакционно. Это не отправка feedback: события прослушивания, пропуска и лайка в радио, а также история провайдера остаются непроверенными и не отправляются. После перезапуска сохранённая очередь воспроизводится, но для новых рекомендаций нужна новая радиосессия.

Таймаут записи не означает, что сервер её отклонил: слепой повтор способен продублировать вставку или событие. После неоднозначного результата изменения плейлиста сначала получить свежий снимок и ревизию и сообщить о результате; не воспроизводить позиционную операцию автоматически. Для событий не доказан серверный ключ идемпотентности: локальный ID не даёт гарантии дедупликации, поэтому автоматический повтор после неоднозначного ответа также недопустим.

| Операция | Статус | Ограничение |
| --- | --- | --- |
| Создание, чтение, вставка, удаление плейлиста/трека | Подтверждено live | Только отдельные тестовые списки; UI проверяется fixtures |
| Перестановка и устаревшая ревизия | Подтверждён ограниченный live-сценарий | Не записан формат серверной ошибки; не доказана атомарность при сбое |
| Переименование | Требует ручного прогона | Happy path был успешен, ревизии до/после не сохранены; API/UI не подключены |
| Радиосессия и следующая партия | Подтверждено live | Без воспроизведения и feedback; партии могут пересекаться |
| Feedback и запись истории | Требует ручного прогона | Транспорт выключен, идемпотентность не доказана |
| Окончательный отзыв/восстановление офлайн-прав | Не поддерживается до определения сигнала | Общие HTTP-коды и `available` не меняют права |

Лайки меняются только по явной команде. При ошибке ответа на запрос изменения интерфейс возвращает прежнее локальное состояние, хотя сервер мог принять запрос; до обновления с сервера фактическое состояние не подтверждено.
