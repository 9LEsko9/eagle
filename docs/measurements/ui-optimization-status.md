# Оптимизация UI: реализация и принятие результата

Дата: 2026-11-13. Машина замеров: Mac14,15, Apple M2, 8 ГБ RAM, macOS 27.2.
Единицы бюджета: 1 МБ = 1 000 000 байт; МиБ = 1 048 576 байт.

**Статус: результат принят пользователем, задача закрыта 2026-11-13.**
Пользователь подтвердил появление окна и сообщил о потреблении около **130 МБ**, которое
признал приемлемым. Это пользовательское наблюдение: метрика памяти, единицы и условия
не были инструментально уточнены. Код запуска после сообщения об отсутствии окна не менялся;
причина задержки появления окна не установлена.

Исходные строгие бюджеты 90/100 МБ, presentation timing, 30-минутная матрица и реальный
внешний 4K не подтверждены. Они не являются обязательством по продолжению закрытой задачи;
дальнейшие аппаратные замеры или оптимизация требуют отдельного задания.

## Что изменено

- Slint 1.17.0: FemtoVG/WGPU по умолчанию, software явно выбирается флагом;
  тип Renderer используется desktop, bootstrap и screenshot-примером.
- Виртуальные карточки с overscan в одну строку и привязкой resize к исходному элементу;
  та же сетка на исполнителе. Загрузки в ограниченном ListView, подтверждение удаления
  хранится снаружи повторяемых строк. Виртуальные списки треков и очереди сохранены.
- Панель освобождает дерево после анимации; редактор, выбранное вхождение и scroll
  очереди вынесены в Ui. Состояние переживает сворачивание панели и уничтожение окна: Shell сохраняет
  его отдельно и восстанавливает после получения новой очереди из Session.
- Общий cover worker для player/header/thumbnail. Ключи адресата отделены от ключей
  декодирования: контекст всех подключённых аккаунтов, provider, URI либо старый stem,
  размер. Файлы кэша и схема БД не менялись. Отдельный decoded cache каталога удалён;
  приложение сохраняет byte-based LRU ≤16 МиБ, bridge переиспользует slint::Image
  только среди текущих получателей. Размеры 64/300/600 не уменьшены.
- Ограничения входа 2 МиБ, 1200×1200, decoder max_alloc 8 МиБ. Повреждённый кэш
  повторно скачивается при наличии источника. Ошибки worker диагностируются без URL.
  Параллельное тяжёлое декодирование из подготовки офлайн-файлов сериализовано.
- Отмена artwork на смене экрана/аккаунта/закрытии; cancellation token проверяется
  до преобразования в Slint. Учтена смена аккаунта вторичного провайдера.
- Одна запланированная пакетная доставка событий; coalescing заменяемых состояний
  сохраняет структурные барьеры. Pending artwork ≤8 МиБ, потерянные миниатюры
  запрашиваются заново. Mutex освобождается перед доставкой. Бюджет 2 мс кооперативный:
  одно тяжёлое структурное событие может длиться дольше и требует отдельного профиля.
- QueueOrder обновляет только current при неизменном порядке; полная модель сохраняется.

Skia отсутствует в desktop dependency tree для macOS/Windows/Linux. Его записи
сохраняются в Cargo.lock: Slint/Winit 1.17 требует Skia для Apple-платформ кроме macOS.
Удалять обязательные записи lockfile вручную нельзя.

## Сценарий и достоверность измерений

`bench/desktop.py` готовит данные до измеряемого процесса: 10 000 треков,
1 000 карточек, 1 000 offline jobs, очередь из 10 000 записей, смешанные алфавиты,
повторяющиеся либо уникальные PNG. Обычный тестовый provider оставлен на 100 треков.
По умолчанию запускаются три независимых процесса, каждый с новым каталогом.

Самплер пишет полный ряд с запрошенным интервалом 10 мс, фактический максимальный gap,
sampled peak, p95, финальные и последние секундные значения по этапам. Darwin rusage v4
даёт system lifetime peak; v2 остаётся запасным вариантом. Последний короткий участок
завершения процесса после последнего живого sample не наблюдается. Пишутся hash бинарника,
commit/dirty, Rust/Slint, requested renderer; при успешном GUI — backend, physical size,
scale factor и видимость. Frame presentation/GPU completion не подменяются CPU timing.

Подготовленный дисковый кэш не означает холодный OS cache. `--reuse-fixture` допускает
прогретый повтор только для явно маркированного каталога, по одному процессу с отдельным
отчётом. Настоящая cold/warm дисковая матрица остаётся открытой.

Попытки запуска (полные ряды сохранены):

| Отчёт | Наблюдение | Пригодность |
|---|---|---|
| [Skia, первая попытка](ui-skia-baseline-1.json) | Остановлен диагностически после ≈100 с, только startup | Не baseline окна |
| [Skia, повтор](ui-skia-retry.json) | Таймаут 300 с, только startup | Не baseline окна |
| [FemtoVG, диагностика](ui-femtovg-probe.json) | Таймаут 30 с на заранее подготовленной БД, только startup | Не приёмка GPU/окна |

Процессы не зарегистрировали ни idle, ни playing. Фактический graphics API, поверхность
и видимость не подтверждены. Пики этих запусков нельзя сравнивать как выигрыш рендера:
запуски не дошли до одинакового рабочего состояния и шли во время сборок.
Отдельный `sample` Skia показал главный поток внутри запуска AppKit / NSApplication,
включая загрузку WritingToolsUI. `system_profiler SPDisplaysDataType` вернул Apple M2
без списка дисплеев. Системный resolver недоступен; Cargo загрузил зависимости через
временный localhost CONNECT proxy с DNS на 10.20.0.2. Настройки сети Mac не менялись.

## Сценарий для отдельной будущей аппаратной проверки

На машине с доступной графической сессией и реальными Retina/4K, без параллельных сборок:

```sh
cargo build --release --locked -p eagle-desktop
python3 bench/desktop.py --binary target/release/eagle-desktop \
  --fixture-root /tmp/eagle-ui-gpu --renderer femtovg-wgpu \
  --output docs/measurements/ui-gpu.json --runs 3 --artwork unique
```

Повторить для repeated artwork и software, затем полную матрицу размеров, скролла,
resize, переходов экранов и треков, 30 минут и 20 циклов окна. Текущий smoke автоматизирует
только idle/play/pause и несколько циклов закрытия/открытия; стресс-прокрутку, 20 циклов
и длительность 30 минут ещё требуется автоматизировать. Presentation intervals и GPU
render duration снимать отдельным прогоном Instruments/Metal System Trace.

Нужно визуально сравнить FemtoVG со Skia: темы, круглые изображения, тени, текст,
popup, focus и анимации. Выполненный headless software-preview показывает ожидаемые
ограничения radius clipping и теней; он не подтверждает визуальное равенство GPU.
При отдельном возвращении к строгому бюджету следует измерить вклады
Session/models, decoded/pending artwork и GPU. Дизайн и Retina resolution не упрощались.

## Итоговые автоматические проверки

Все команды завершены с кодом 0:

- `cargo fmt --all --check`, `git diff --check`.
- `cargo test --offline --locked --workspace`.
- `cargo build --release --offline --locked -p eagle-desktop -p eagle-cli`.
- Настоящая сборка desktop Rust 1.92: `RUSTC=/private/tmp/eagle-rust192/bin/rustc CARGO_TARGET_DIR=/private/tmp/eagle-ui-msrv cargo build --offline --locked -p eagle-desktop`.
- Восемь Python-тестов самплера; headless software-preview завершён.
- Тесты app/UI/palette включают bounded grid при 1000 карточках и реальные клики
  после scroll/resize, отмену до Slint conversion, освобождение bridge images,
  byte-based eviction, разделение account/provider, image limits, batching barriers,
  сохранение модели очереди при смене current и перенос редактора через новое окно.

Машинный отчёт: [ui-optimization-checks.json](ui-optimization-checks.json).

Это короткий регрессионный smoke CLI, который не запускает Session/UI/audio.
Он не является проверкой фонового бюджета 30 МиБ или бюджета открытого окна.
Предварительный замер с совпавшими hash двух CLI был отброшен; итоговое сравнение
использует разные, зафиксированные в JSON SHA-256. Строки исходных CSV вложены в JSON.

Windows/Linux dependency tree проверены; новые CI-сборки этих ОС не выполнялись
(изменения локальные). Попытка прочесть текущие remote CI через `gh run list`
завершилась ошибкой системного TLS trust `OSStatus -26276`; успешный CI не заявляется.
