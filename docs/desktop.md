# Десктоп: этап 4

Текущие границы реализации и доказательства приёмки: [desktop-beta-acceptance.md](desktop-beta-acceptance.md). Полная desktop-бета не принята до аппаратных прогонов, подтверждения контрактов Яндекса и фактического бюджета памяти.

```sh
cargo run -p eagle-desktop
cargo run -p eagle-desktop -- --software
cargo run -p eagle-ui --example screenshots -- /tmp/eagle-screenshots
```

Slint закреплён на 1.17.0, MSRV поднят до 1.92 по согласованию. `.slint` компилируются через `slint-build`, интерпретатора нет. Android/iOS сохраняют прежние точки входа; новый интерфейс пока только десктопный.

## Оптимизация открытого окна: состояние приёмки

Изменения и результаты: [ui-optimization-status.md](measurements/ui-optimization-status.md).
**Результат принят пользователем 2026-11-13:** окно открылось, наблюдаемое потребление
около **130 МБ** признано приемлемым; дальнейшая оптимизация в рамках этой задачи закрыта.
Метрика и единицы этого пользовательского наблюдения отдельно не проверялись.
Исходные критерии 90/100 МБ, frame timing и Retina/4K формальными замерами не подтверждены.
Сохранённые startup-only прогоны остаются диагностикой, а не замерами открытого окна.

Карточки создаются только для видимых строк с одной строкой запаса сверху и снизу;
загрузки используют ограниченный ListView. Содержимое панели уничтожается после анимации,
состояние редактора и scroll очереди хранится в Ui вне панели. При смене экрана модели
и изображения освобождаются. Доставка событий пакетная, с одним запланированным callback,
лимитом ожидающих изображений 8 МиБ и кооперативным бюджетом прохода 2 мс. Самостоятельное
долгое структурное событие всё ещё может превысить этот бюджет; это требует профиля.

Software функционально проверен headless-сценарием screenshot-примера. Его ограничения:
обрезка изображений по радиусу и тени отличаются от GPU-рендера (например, обложка исполнителя
выглядит квадратной). Он остаётся явно выбираемым режимом.

## Реализовано

- `eagle_app::session`: Command/Event, отдельные потоки каталога и управления, ленивый Engine. Сеть каталога не блокирует команды плеера. Завершение Session закрывает каналы и присоединяет потоки.
- PlayerState передаётся как Arc. Якорь позиции — отдельное событие без копирования метаданных. Мост использует `invoke_from_event_loop` и слабую ссылку на окно.
- LibraryDelta обновляет VecModel по строкам. Ответы устаревших запросов отбрасываются после перехода на другой экран. Плейлисты читаются из локального хранилища.
- Медиатека, поиск, альбом, плейлист, вход в Яндекс токеном с системным хранилищем секретов. Лайки отправляются провайдеру и сохраняются локально.
- Очередь движка, предыдущий/следующий, пауза, перемотка, громкость, перемешивание и повтор. Прогресс интерполируется при видимом окне, 4 Гц только во время воспроизведения.
- Графит / Бумага / OLED / Авто, масштаб текста и уменьшение движения. Цвет обложки считает eagle-palette: нижняя полоса использует k=0.94/0.88, панель — коэффициенты из макета. Оба оттенка проверяются на общий читаемый текст.
- Обложки плеера, заголовка и миниатюр проходят через общий worker с приоритетами. Декодированный LRU ограничен 16 МиБ; отдельный кэш каталога удалён. Входные изображения: до 2 МиБ, 1200×1200, decoder allocation limit 8 МиБ.
- По умолчанию запрашивается FemtoVG/WGPU (`--renderer=femtovg-wgpu`). Явный `--renderer=software` и совместимый `--software` выбирают запасной режим; конфликтующие флаги отклоняются. Автоматический переход на software не выполняется. WGPU notifier сохраняет фактический backend при успешной инициализации. Аппаратная приёмка нового рендера остаётся открытой.
- Souvlaki подключён к командам app и метаданным. AccessKit включён; элементы имеют подписи, фокус и клавиатурные действия.
- Строки интерфейса используют `@tr`; русские формы числительных встроены из gettext. Inter содержит подмножество латиницы и кириллицы с OFL.
- Один экземпляр, повторный запуск разворачивает окно. Размер, положение, тема и состояние панели сохраняются; положение восстанавливается только на доступном мониторе.

Winit не сообщает свёрнутость на Wayland. Там используется консервативный режим: интерполяция и доставка позиций в UI останавливаются при потере фокуса, позиция восстанавливается при возвращении. Видимое окно без фокуса на Wayland пока не показывает плавный прогресс. На платформах с поддержкой состояния свёрнутости фокус не ограничивает видимое окно.

Постоянная оболочка сохраняет Session после закрытия и уничтожает Slint-окно. Повторное открытие создаёт новое окно и получает согласованный снимок. Настройка позволяет завершать процесс при закрытии. Освобождение renderer/GPU и бюджет фоновой памяти проверяются отдельно; сам по себе drop окна их не доказывает.

## Внутренняя бета: состояние реализации

Реализованы оболочка, постоянная очередь, загрузки, автономный доступ и перенос. Полная бета ещё не принята: контракты Яндекса и аппаратные критерии остаются открытыми; автоматические проверки не заменяют сквозную приёмку.

- SQLite schema v2 добавляет отдельную таблицу `playback` по подтверждённому
  UID аккаунта. Очередь содержит метаданные, постоянные идентификаторы каждого
  вхождения трека, исходный и текущий порядок, текущий элемент, позицию,
  shuffle/repeat. Аудиоссылок в этой таблице нет. Миграция v1 → v2 сохраняет
  существующие таблицы; старый бинарник с поддержкой только v1 откажется
  открывать v2. Текущая schema v8 дополнительно хранит задания загрузки, локальную историю, решения о доступе, outbox, владельцев аудио и контекст радио для локальных намерений прослушивания;
  бинарники с поддержкой только v1/v2 её не откроют. Для отката версии нужна
  резервная копия БД до обновления.
- Запуск восстанавливает очередь на паузе, без создания Engine и без запроса
  аудиоссылки. Resume создаёт Engine и перематывает к сохранённой позиции.
  Next/Previous до Resume меняют выбор без открытия аудиоустройства.
- Сохранение выполняется при действиях пользователя, смене трека, паузе,
  остановке и выходе. Во время воспроизведения позиции записываются с шагом
  не чаще 10 секунд по таймауту потока управления и событиям Engine.
  Вне воспроизведения поток управления ждёт команды без такого таймаута. Новый снимок окна запрашивается через
  `Command::Snapshot` и поступает одним `Event::Snapshot`, перед последующими
  событиями потока управления. UI-мост умеет восстановить из него модели,
  плеер и позицию при уничтожении и повторном создании окна.
- `MoveQueue { id, to }` и `PlayNext(id)` работают с точным вхождением очереди;
  `EnqueueNext(track_id)` добавляет новое вхождение из локальных метаданных.
  Команды подключены к кнопкам, клавиатуре и перетаскиванию; фокус перестановки хранится по ID вхождения.
- Смена аккаунта останавливает предыдущую очередь и очищает личное состояние
  видимого экрана; очереди разных UID сохраняются раздельно. Общие метаданные
  и аудиофайлы используют общий физический кэш, но право на его чтение хранится отдельно по аккаунту и треку. Чужой или неразмеченный файл требует подтверждения текущего аккаунта до чтения; явный отзыв доступа сохраняет файл на диске.
- Закреплённое аудио исключено из лимита LRU. `Cache::usage` возвращает отдельно
  байты незакреплённого и закреплённого аудио; обложки и SQLite туда не входят.
  Закрепление полного файла меняет sidecar и индекс, сохраняя сам аудиофайл.

- Schema v3 хранит задания по UID, track ID и выбранному качеству. Повторное
  добавление не дублирует задание. `Command::Save`, `Downloads`,
  `PauseDownload`, `CancelDownload`, `RetryDownload` и `Event::Downloads`
  подключены к Session, экрану хранилища и кнопкам сохранения.
- Исполнитель имеет два физических слота, использует фоновый приоритет общего
  HTTP-клиента и ждёт сообщения без периодического таймера, когда работы нет.
  При запуске running → queued; paused и cancelled остаются такими до явного
  действия. Выход отменяет текущие попытки и оставляет их queued для запуска.
  Ревизии не позволяют запоздалому результату отменить пользовательскую паузу,
  отмену или смену аккаунта. Смена учётных данных ждёт остановки прежних попыток.
- URL получается заново для каждой попытки и обновляется сетевым загрузчиком
  при истечении/401/403/410; в SQLite и карте диапазонов его нет. Частичный
  staging-файл возобновляется только с сильным ETag. При смене ресурса или
  ответе 200 вместо запрошенного продолжения файл один раз перезапускается с
  нуля. Без сильного ETag объединение разных HTTP-ответов отклоняется.
- Яндекс High требует MP3 320 кбит/с без preview; молчаливого перехода на
  более низкий битрейт больше нет. Standard выбирает лучший MP3 от 1 до 192
  кбит/с. Отсутствие варианта возвращает `UnsupportedQuality`; загрузка сохраняет
  отдельное фиксированное пояснение ошибки в SQLite с защитой по ревизии.
  Сетевые ошибки и проблемы входа не считаются отсутствием качества.
  `Stream`, загрузчик и карта кэша передают заявленный провайдером битрейт.
  Поле карты обратно совместимо: старые файлы читаются с неизвестным битрейтом,
  без вывода значения из названия High/Standard. Новые данные переживают
  закрепление и повторное открытие. Состояние плеера и его снимок получают
  битрейт выбранного источника, включая локальный файл другого качества.
  События ограничены поколением движка и идентификатором вхождения очереди:
  preload повторного трека не меняет данные текущего. Старый кэш автоматически
  не переклассифицируется. Значение отражает объявление провайдера, а не анализ
  кадров аудио. Slint показывает переданный битрейт или явное «Битрейт неизвестен».
- Файлы заданий лежат в `audio/downloads/<job-id>`, отдельно от аудио плеера.
  Готовый файл атомарно переименовывается в кэш на той же файловой системе и
  закрепляется. Если целевой файл занят плеером, задание завершается ошибкой
  для явного повтора после освобождения. Уже готовое аудио выбранного качества,
  подтверждённое для текущего аккаунта, закрепляется на месте без HTTP,
  копирования и создания staging-файла. Файл без владельца требует онлайн-проверки
  аккаунта и разрешения потока; само аудио при этом повторно не загружается.
- `Saved` публикуется после закрепления аудио, записи метаданных, обложек 64/600 px
  и цвета. При отсутствии обложки у провайдера сохраняется постоянная заглушка.
  Обложки записываются через уникальные временные PNG, синхронизируются и
  переименовываются до записи цвета и статуса. Существующие файлы декодируются
  перед повторным использованием; повреждённые восстанавливаются. Ошибка
  метаданных оставляет аудио закреплённым для явного повтора без HTTP аудио.
  Старые `AudioReady` при запуске возвращаются в очередь для завершения.
  Отмена очищает staging после завершения физического работника;
  приостановленные и прерванные процессом задания сохраняют диапазоны для
  восстановления. Staging учитывается отдельно в экране хранилища.
  Завершение HTTP в полёте ограничено таймаутом сетевого клиента.

Автотесты проверяют миграцию v1, сохранение по аккаунтам, повторные треки,
восстановление на паузе, позицию и ограничение частоты записи, перестановку,
добавление следующего вхождения, применение снимка в Slint и защиту pinned от
LRU. Новые fixtures проверяют два конкурентных claim, ревизии отмены/повтора,
восстановление running, изоляцию заданий по UID, закрепление без resolver,
докачку с If-Range, смену ETag, исчезновение Range и защиту файла плеера.
Проверяются также публикация `Saved`, устаревшее завершение после отмены,
доработка `AudioReady`, постоянная заглушка и офлайн-восстановление испорченной
обложки. Интеграционная проверка прошла fmt, clippy с `-D warnings`, MSRV 1.92
и единый прогон workspace (183 теста). Session и UI используют внедряемый
fixture-провайдер без Keychain; HTTP-fixtures требуют разрешённых локальных
сокетов. Отдельный тест убивает дочерний процесс во время загрузки и после
перезапуска докачивает 100 fixture-треков. Он проверяет декодирование аудио и
заранее созданных PNG, а не 100 полных воспроизведений или сетевое получение
обложек. Перезапуск использует тот же test executable: обновление сборки,
отмена во время аварии и реальный сценарий Яндекса остаются непроверенными.

При миграции старый pinned-файл без задания загрузки не получает владельца
автоматически: прежний формат не доказывает, какому аккаунту принадлежали права.
Файл остаётся на диске, но для офлайн-доступа требуется онлайн-подтверждение
текущего аккаунта. Это ограничение совместимости; одной текущей записи UID
недостаточно для безопасного переноса прав.

Интерфейс загрузок и локальные разделы:

- Меню трека: «Играть следующим» и «Сохранить офлайн». Кнопка списка сохраняет
  все его загруженные в ядро строки одной транзакцией; одинаковые ID/качество
  не дублируются. Повторное нажатие не возобновляет приостановленные задания.
- Настройки показывают состояние и безопасную ошибку задания, паузу/продолжение/
  отмену; выбор качества относится только к новым заданиям и сохраняется сразу.
- Завершённое сохранение удаляется с подтверждением. Активный файл защищён
  lease; файл другого аккаунта сохраняется, пока тот на него ссылается.
  При сбое удаления запись уже перестаёт считаться сохранённой; остаточные
  файлы могут остаться на диске. Отмена очищает staging после завершения физического работника; незавершённые задания сохраняют диапазоны для восстановления.
- Аудиокэш, закреплённое аудио, staging и прочие данные показаны отдельно. Общий логический размер учитывает файлы управляемой папки, включая обложки, SQLite и служебные файлы.
  Лимит 512 МиБ / 2 ГиБ / 8 ГиБ сохраняется в SQLite и применяется к новым
  записям; активные читатели и закреплённые файлы защищены.
- Системный монитор сети и пользовательская политика управляют фоновыми загрузками без ограничения пользовательского воспроизведения. Unknown разрешает загрузки с пояснением; известная лимитная сеть по умолчанию запрещает их. Реальные переключения сети требуют аппаратной проверки.
- Полная очередь в панели использует ID вхождений; доступны кнопки ↑/↓,
  клавиши ↑/↓, перетаскивание и действие «Следующим».
- Раздел «Сохранённое» читает завершённые задания текущего UID из SQLite.
  Локальная история (schema v4) записывает трек после первой секунды звучания,
  сохраняет отдельные повторные прослушивания и показывает последние 1000 записей.
  Старую историю аккаунта не импортирует, события провайдеру пока не отправляет.
- Настройки оформления записываются при действии, без периодического таймера.
  Длительности: цвет 350 мс, панель 250 мс, play/pause 200 мс, сердце 2×200 мс;
  уменьшение движения задаёт нулевую длительность и выключает таймер сердца.

Следующие блоки плана остаются открытыми:

- Оставшаяся матрица HTTP-fixtures (обрыв/нехватка диска/перезапуск процесса),
  отмена во время HTTP, приёмка приоритета активного воспроизведения,
  приёмка отмены из интерфейса во время реального HTTP.
- Подтверждение провайдером однозначной семантики отзыва/восстановления доступа; локальные состояния и суточный интервал реализованы.
- Аппаратные проверки переноса между томами, нехватки места и системного статуса лимитного подключения. Журнал, проверка данных, переключение и восстановление реализованы.
- Отправка событий Волны/истории и их безопасный повтор, полная семантика ошибок
  ревизии и переименования. Получение рекомендаций и позиционное редактирование
  плейлистов подключены; локальные намерения ещё не являются подтверждёнными
  провайдером событиями. Реальная отправка событий в этом прогоне запрещена.
- Аппаратная приёмка перетаскивания, компактных строк и завершения анимаций.
- Независимая от окна оболочка, tray-icon/muda/ksni, освобождение renderer/GPU,
  watcher Linux, Dock macOS, уведомление первого закрытия, автозапуск и выход.
- Сквозной прогон 100 треков, офлайн после обновления/аварии, Windows/Linux,
  Wayland/X11, системные медиаклавиши без окна и фактический бюджет 30 МиБ.

Исходный release CLI (`4824682`), macOS arm64, синтетический idle по 5 секунд:
1 868 184 байт phys_footprint, CPU 0%, package/interrupt wakeups 0/0.

## Поиск и управление плейлистами

В поиске можно выбрать треки, артистов, альбомы или плейлисты. При смене
категории сохраняется введённый запрос; карточка открывает соответствующий
экран, а альбом — список его треков. Пустой запрос очищает выдачу без HTTP.
Переходы в альбом также доступны из
строк треков, плеера и дискографии артиста.

Создание плейлиста доступно из боковой панели: введите название и подтвердите
создание. Новый плейлист создаётся в Яндекс Музыке приватным и открывается даже
без треков. Удаление доступно в заголовке своего плейлиста, с подтверждением
названия. Провайдер дополнительно проверяет владельца перед отправкой запроса.
После успешной операции обновляется локальный список и боковая панель; ошибка
запроса сохраняет прежние данные. Запоздалый ответ не меняет экран, на который
пользователь успел перейти. Операции выполняются в потоке каталога, отдельно
от воспроизведения.

Локальный личный кэш привязан к подтверждённому UID Яндекса. При смене UID
старые лайки и список плейлистов сбрасываются до начала новой синхронизации;
общие метаданные треков и скачанное аудио сохраняются. Повторный вход в тот же
аккаунт сохраняет его кэш. Сбой одного раздела фоновой синхронизации не мешает
обновлению остальных; открытые списки альбомов и артистов обновляются по готовности.

Контракт запросов и обработка ошибок проверяются локальным HTTP fixture;
создание и удаление в реальном аккаунте при автоматических проверках не
выполняются. Новое поле обложки плейлиста совместимо со старыми JSON-записями
SQLite и не требует миграции.

## Основа дизайна

Пользовательский файл `eagle — макеты и темы.html`: десктопный плейлист и три темы. Перенесены токены, двухстрочные ряды фиксированной высоты 54 px, текстовая навигация, заголовок с обложкой, центральные транспортные кнопки над прогрессом и отдельный оттенок правой панели. Автоматические проверки выполняются отдельно от ручной приёмки. Тест Slint проверяет доступное действие лайка, смену темы и отсутствие вызовов таймера прогресса в скрытом состоянии. Контраст проверяется на сетке из 36 864 сочетаний цвета обложки, темы и интенсивности. App проверяет применение дельт, офлайн-медиатеку, интерполяцию и остановку потоков.

Полный `cargo deny` содержит точечные исключения для архивных транзитивных пакетов Slint/AccessKit (ID и причины — в deny.toml). RustSec не сообщает уязвимостей; предупреждения `cargo audit` о неподдерживаемых пакетах сохраняются. Их миграция требует обновления закреплённого UI-стека.
