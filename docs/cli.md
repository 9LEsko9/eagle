# CLI и хранилище

Для проверки нужен отдельный тестовый аккаунт с доступом к Яндекс Музыке.
Получите OAuth-токен по [инструкции автора Yandex Music API](https://ym.marshal.dev/token/).
Вход через пароль Яндекса внутри eagle не реализован. Выполните login и вставьте
только токен в скрытый интерактивный ввод. Не передавайте его аргументом команды,
не сохраняйте в config и не отправляйте в issue. После проверки `/account/status`
токен сохраняется в системном keyring (macOS Keychain, Windows Credential Manager,
Linux Secret Service). На Linux нужна работающая пользовательская D-Bus-сессия и
разблокированное хранилище секретов.

```sh
cargo run -p eagle-cli -- yandex login
cargo run -p eagle-cli -- yandex status
cargo run -p eagle-cli -- yandex search "исполнитель трек"
cargo run -p eagle-cli -- play yandex:123
# Та же команда поддерживается с префиксом yandex:
cargo run -p eagle-cli -- yandex play yandex:123
# Закрепить полную копию от вытеснения:
cargo run -p eagle-cli -- play yandex:123 --save
# Диагностика загрузки без аудиоустройства:
cargo run -p eagle-cli -- play yandex:123 --download-only
```

Замените `yandex:123` на ID из поиска. По умолчанию выбирается полный MP3 до
320 кбит/с, `--standard` ограничивает выбор 192 кбит/с. Preview не выбирается.
Протокол опирается на [реализацию DownloadInfo](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/download_info.py).
Наблюдения потоков и ограничения: [спайк](engine-format-spike.md).
Поддержка lossless и шифрованного API провайдера пока не заявляется. 2026-11-12 владелец подтвердил живой вход, поиск, звук и повторное
воспроизведение без интернета для тестового трека. Локальные HTTP-тесты отдельно
проверяют обновление истёкшей ссылки; принудительное истечение ссылки на живом API
не проверялось.

CLI сначала ищет закреплённую копию (любого качества), затем кэш нужного качества.
При попадании в кэш не запрашивает токен, метаданные или URL. На сетевом пути
диапазоны по 2 МиБ запрашиваются по мере чтения; звук начинается до полной
загрузки. Без потребности в данных сетевые потоки ждут Condvar.
После успешной загрузки CLI печатает число HTTP-заданий и байты прочитанных тел
ответов. Повторный запуск должен показать `0 запросов, 0 байт ответов` и работать
при отключённой сети. Эти счётчики не включают заголовки/TLS/TCP и не являются
измерением пробуждений радиомодуля. HTTP 401/403/410 у аудиоссылки вызывает
повторный resolve с ограниченным числом попыток. Истёкший OAuth-токен требует login.

Другие команды: `yandex likes`, `playlists`, `album yandex:ID`,
`playlist yandex:OWNER_KIND`, `like yandex:ID`, `unlike yandex:ID`,
`dislike yandex:ID`, `undislike yandex:ID`, `sync`.
Unlike снимает лайк; dislike ставит отдельную отметку «не рекомендовать».
Синхронизация выполняется после login, своих лайков/дизлайков и по `sync`.
Для CLI отдельного события возврата в окно нет; cached play намеренно не запускает
синхронизацию. ID лайков забираются одним ответом API, полные треки — пачками
по 100 без лимита в 10 000. Список плейлистов API отдаёт целиком.

## Хранилище и восстановление

Данные находятся рядом с logs в каталоге Eagle; `EAGLE_DATA_DIR` меняет корень.
SQLite работает в WAL с `user_version=1`; записи выполняет один `eg-store`,
чтения открывают короткоживущие read-only соединения. Схема содержит треки,
альбомы, исполнителей, плейлисты, лайки, кэш, палитры и настройки.
Кэш ограничен 2 ГиБ; незакреплённые файлы вытесняются по последнему обращению.
Сохранённые копии учитываются в лимите; если весь лимит закреплён, загрузка
останавливается с объяснением. Обложки сохраняются только в размерах до 64 и
600 px, палитра получается медианным сечением по 32×32 и записывается один раз.

У аудиофайла есть JSON-карта полузакрытых диапазонов `[start,end)`, размера,
ETag и флага закрепления. Байты синхронизируются до атомарной замены карты.
Дыры никогда не считаются загруженными; повреждённая карта и её аудиофайл
отбрасываются при открытии кэша. Незавершённая загрузка с ETag продолжается после
обрыва, без ETag начинается заново. При ошибке записи (включая отсутствие места)
скачивание прекращается; неуспешный диапазон не публикуется в SQLite.
Повреждённая SQLite сохраняется как `corrupt-*.sqlite`, создаётся новая база,
кэш и закрепления восстанавливаются из карт. Метаданные восстанавливает `sync`;
новую неизвестную версию схемы приложение не перезаписывает.

Решение для текущего CLI: аудио на диске **не шифруется**. На Unix корень данных
имеет права 0700; шифрование ключом из keyring остаётся отдельным продуктовым
решением. Текущая версия не обеспечивает ограничение «офлайн только внутри eagle».
CLI принимает смешанную очередь файлов, URL и ID Яндекса; недоступный трек
сообщается как ошибка и пропускается. Перемотка за загруженные данные требует Range.
Активные reader удерживают временную аренду кэша; будущий элемент очереди
повторно проверяет кэш при открытии и при необходимости получает ссылку заново.
Одновременные процессы с общим каталогом данных пока не поддерживаются.


## Очередь и управление

```sh
cargo run -p eagle-cli -- play song.flac https://example.org/song.mp3 yandex:123 --buffer-seconds 2
```

Space — пауза; ←/→ — ±10 секунд; `n` — следующий; `+`/`-` — громкость; `q` — выход.
`--stats` печатает кадры, underruns, callbacks, HTTP и частоту выхода.
Буфер: 2–20 секунд. `--` завершает разбор флагов для путей с ведущим дефисом.
`--save` и `--download-only` полностью загружают очередь перед воспроизведением.
Режим терминала восстанавливается RAII-guard при обычном выходе и ошибке.

Устройство и ограничения кодеков описаны в [engine.md](engine.md).
