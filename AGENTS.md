# Инструкции для работы с проектом

## Код

- Проект написан на Rust (edition 2024). Основной стандарт — [Google Rust Style Guide](https://google.github.io/styleguide/rustguide.html): следуй его общим правилам для форматирования, API и реализации. Правила, предназначенные специально для Chromium, Fuchsia и других отдельных проектов, применяй только если они подходят этому проекту.
- Используй `rustfmt` и официальные соглашения Rust там, где они не противоречат руководству Google.
- Пиши простой, читаемый код; выбирай понятные имена и не добавляй абстракции или зависимости без необходимости.
- Обрабатывай ошибки явно, не используй `unwrap` и `expect` в рабочем коде без обоснования.
- Добавляй тесты для нетривиальной логики и исправлений ошибок. Перед завершением изменений запускай подходящие проверки, как минимум `cargo fmt --check` и `cargo test`, если они применимы.
- Не включай секреты, артефакты сборки и локальные файлы Claude в репозиторий.

- MSRV: Rust 1.85. Общие зависимости: `thiserror` для ошибок и `log` для логов; `tracing` не использовать.
- Для замеров: `cargo xtask bench` (нужен Python 3.9+). Результаты каждого этапа сравнивай с baseline на той же машине.
- Логи доступны с этапа 0: используй `log` с kv; на info пиши только provider/track_id, без названий и поисковых запросов. Секреты храни в `eagle_core::Token`/`SignedUrl`, не логируй `expose()`. Бэкендная маскировка — только страховка.
- Не используй OpenCode для работы над проектом.

## CodeGraph

- Если в корне есть `.codegraph/`, начинай работу с кодом с `codegraph_explore`: указывай в запросе соответствующий файл или символ до текстового поиска и чтения кода.
- Если MCP-инструмент недоступен, используй `codegraph explore`. Если индекса нет, не создавай его без запроса пользователя.
- Индекс и служебные файлы CodeGraph локальные и не коммитятся.

## Коммиты

- Формат первой строки: `[INIT] описание`, `[FIX] описание`, `[FEATURE] описание` или `[DEV] описание`.
- Описание должно кратко объяснять изменение. Остальные строки сообщения можно использовать для деталей.
- Для локальной проверки сообщений выполни `git config core.hooksPath .githooks` после клонирования.
